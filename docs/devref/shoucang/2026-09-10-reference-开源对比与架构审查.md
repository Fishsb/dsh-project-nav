# project-nav · 开源同类对比 + 自身架构审查（2026-09-10）

> 方法：检索 AI 编码治理/规范驱动相关开源项目与经典架构治理框架，逐项对照本插件现有能力，标出**不足**与**冗余**。所有「已实现」判断均以源码/工具实跑为依据（v0.5.0，13 工具）。

## 一、同类项目对照

| 体系 | 核心机理 | 对本插件的启示 |
|---|---|---|
| **OpenSpec**（Fission-AI，SDD） | `specs/` 为真相、`changes/` 为待办变更提案，propose → apply → archive 三段闭环；先对齐「要做什么」再写码 | 本插件 v0.2.5 已对齐其 archive 语义（done 时 delta 收口）；**未吸收**其「变更提案文档」形态——本插件用动作账本 JSON 代替 |
| **GitHub Spec Kit** | 顶层 `constitution`（不变量）+ specify → plan → tasks → implement 四段；先立宪法再谈实现 | 本插件缺「**宪法/不变量**」一等公民：主线向量 `notDoing` 只防方向，不承载架构不变量。v0.5.0 的 ADR 是候选落点 |
| **ADR（Nygard）** | 决策 = 上下文 + 决策 + 后果，一次一档、可回溯 | v0.5.0 的 `nav_adr` 已实现（anchor/reason/decision/impact）；**但落点在 gitignore 的 `.internal/`**，不可随仓库传播 ⚠ |
| **arc42** | 文档模板按架构视图分节（构建块/运行时/部署/横切） | arch-view 的 L1/L2 分层与之一致；arc42 的「横切概念」一栏本插件无对应（横切约定散在 AGENTS.md） |
| **Backstage catalog / TechDocs** | 组件目录 + 文档与组件绑定，人可查询 | 本插件的索引即 catalog（且 agent 可写）；缺「组件所有者/生命周期」字段 |
| **Policy-as-code（OPA/Terraform）** | 策略与执行分离，违规在**执行前**拦截 | 本插件的闸门即 policy 层，且已做到 **fail-loud 拒绝登记**（锚点闸/主线闸），机制上不弱于同类 |

### 对比结论

- **强于同类之处**：① 闸门是**可执行的**（拒绝登记 + 可查询输出），多数同类只提供文档约定；② **索引由 agent 自己维护**（写路径完整），而非人工维护的 catalog；③ 文档自动派生（`nav:auto` 标记区）从机制上消除「文档与代码漂移」这一同类通病。
- **弱于同类之处**：① 无「宪法/不变量」层；② 决策不随仓库传播；③ 无组件所有者/生命周期语义。

## 二、架构不足（按严重度）

| # | 严重度 | 不足 | 证据 | 建议 |
|---|---|---|---|---|
| G1 | 🔴 高 | **决策不可传播**：ADR 与补丁账本落在 `.internal/`，被 `.gitignore` 排除 | 仓库 `.gitignore` 含 `.internal/`；`nav-arch.json` 只在本机工作区 | 决策迁 `docs/adr/*.md`（或 `.internal/nav-arch.json` 加白名单例外） |
| G2 | 🔴 高 | **索引写路径无互斥**：v0.4.0 只给动作账本加了跨进程锁，索引仍是无锁读-改-写 | PN-P01 索引被反复回退（v0.2.9 清理过又复现，本次再修一次） | 索引写入复用 `withLedgerLock`（或按文件粒度加锁） |
| G3 | 🟡 中 | **沙箱不兼容**：`shared/index.js` 直接依赖 `node:fs`；而 DSH 的沙箱能力是 `ctx.fs`（全异步） | `dsh-fs` 提供 `resolve/stat/readText/writeText/editText/listDir`，**无独占创建原语** | fs 能力注入改造；锁退化为「进程内队列 + 陈旧守卫（`replaceIfVersion`）」，且降级必须显式告警 |
| G4 | 🟡 中 | **锚点粒度止于节点，未覆盖「影响面越界」** | 锚点为 PN-F01 却改到 3 个模块时，只有 `unknown` 软提示 | 计数闸之外加「范围越界闸」：scope 命中锚点之外的模块 → 要求 ADR |
| G5 | 🟡 中 | **无「不变量/宪法」层**：架构文档是描述性的，缺少「不得违反」的硬约束集 | 现有闸门只查主线 notDoing 子串 | 在 arch 文档头部支持 `<!-- arch-invariants -->` 块，`nav_plan` 命中违反项直接拒绝 |
| G6 | 🟠 低 | **架构文档与动作账本没有强绑定**：`nav_plan` 只给「参考文档建议」，不校验锚点对应的架构档是否过期 | `nav_mark done` 的 delta 只提示索引缺口，不提示架构档过期（SKILL.md 自己也标注「未实现」） | done 时比对锚点架构档指纹，过期即提示重生成 |

## 三、架构冗余（可收敛项）

| # | 冗余 | 说明 | 建议 |
|---|---|---|---|
| R1 | **两套指纹机制** | `verifyScopeFingerprint`（动作 scope 文件）与 arch-view 的 `arch-cache`（架构档依赖文件）是两份同构实现，各算各的 | 抽一个 `fileStamp/snapshot` 公共原语供两者复用（本插件已导出 `snapshotScopeFiles`，arch-view 可直接调） |
| R2 | **向量三处** | `vector.json` 的 doing/next/notDoing/exitCondition 同时出现在 `PROJECT.md` 自动区与各项目文档「当前阶段」节 | 保留 SSOT：`vector.json` 为唯一写入口，其余只读派生（现状已如此，但需在 AGENTS.md 明确禁止手改派生处） |
| R3 | **文档层三套载体** | 交付说明 `README` / 交接日志 `HANDOFF` / 架构档 `.internal/arch` —— 「哪份是权威」无显式声明 | 在 `README` 与 `HANDOFF` 头部加一句权威边界声明（README=对外契约，HANDOFF=工程日志，arch=架构真相） |
| R4 | **工具边界重叠表象** | `nav_status`（状态）与 `nav_map`（地图）输出信息高度重叠，易被误当两件事 | 文档已声明边界（状态视图 vs 逻辑视图），保留；仅在 README 工具表补一句「二者分工」 |

## 四、结论

- 核心理念（架构出发 + 第一性原理）此前**只存在于人的约定与文档纪律里**，v0.5.0 首次落成三个机器闸门（锚点/计数/决策），这是本次最重要的架构补齐。
- 最紧迫的两项不是「理念」，而是**传播性**（G1 决策不进 git）与**并发安全**（G2 索引无锁）——两者都会让治理成果在跨机器/跨会话时丢失，属于架构级缺陷。
- 冗余项均属「同构重复」而非「功能重复」，收敛收益中等，建议按 R1 → R3 → R2 顺序处理。
